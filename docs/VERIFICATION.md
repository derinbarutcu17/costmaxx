## Current state (2026-09-02 implementation pass)

This section records the changes made after the 2026-08-05 audit. The
historical audit below remains accurate for the version it describes.

- **Idempotency retries are atomic and orphan-free.** The shared pipeline
  pre-checks the immutable ledger by idempotency key before storing an
  artifact file, and a duplicate retry is answered from the stored evidence
  (`pipeline.RenderStored`) — the byte-identical envelope with the same
  artifact id, one ledger/artifact/reduction row, no second file, and no
  unreferenced file left behind. A post-hoc `PurgeOrphanArtifact` guards the
  remaining store-then-record window. An empty call reference is assigned a
  fresh per-invocation id, never a content-derived key, so independent
  identical calls can never collapse into one row.
  Coverage: `tests/unit/ledger_test.go` (deterministic retry, different-input
  retry, no-ref calls count separately, same-ref replay leaves no orphan),
  `tests/integration/idempotency_test.go` (CLI cross-subprocess + MCP
  boundary), `tests/integration/gc_test.go` (concurrent same-ref dedupe to one
  row; concurrent independent calls all count).
- **CLI call identity is honest: independent invocations count separately by
  default.** `costmaxx artifact add` assigns a fresh unique call reference per
  invocation, so two independent identical invocations are two real calls and
  both are recorded. Passing `--call-ref`/`--idempotency-key` opts into retry
  deduplication: the same explicit ref re-derives the same ledger idempotency
  key, and the pipeline replays the canonical stored envelope (byte-identical,
  same artifact id) instead of recording a second call — deterministic replay
  semantics even when the retried input differs.
- **MCP idempotency boundary is honest and tested.** Idempotency is scoped to
  one server process (one client session, `session_id = mcp-<uuid>`): a
  same-id retry is answered from stored evidence without re-execution. A new
  subprocess is a distinct session and the same JSON-RPC id is recorded
  separately — dedup across sessions would be incorrect and is not claimed.
- **Codex hooks persist atomically and count only real calls.** `PostToolUse`
  writes the artifact, reduction, and ledger row in one `RecordCall`
  transaction; the in-process metrics and the compatibility `session_metrics`
  row are updated only for a newly inserted call with per-call deltas (the
  previous cumulative-snapshot write and the pre-insert metric increment both
  inflated counters on a duplicate retry). A PostToolUse with empty output is
  still a real, observable call: it records a zero-byte ledger row with no
  invented saving. The ledger records the real input cwd (falling back to the
  session repository) and the redacted command. All DB errors in the hook path
  fail open into an observable `error` ledger row instead of being ignored.
  Coverage: `tests/integration/hooks_test.go` (duplicate PostToolUse
  in-process and cross-process — persisted metrics AND in-process Snapshot
  unchanged on the duplicate, empty-output call, cwd + redaction),
  `tests/integration/hooks_observe_test.go`.
- **Negative verifier is a real failure demonstration.** `verify-active-path.py
  --negative` corrupts a stored digest and re-runs the integrity check, which
  now exits non-zero with `FAIL: digest mismatch …` instead of catching and
  reporting a swallowed internal PASS. Coverage:
  `tests/integration/verify_active_path_test.go` (positive exit 0, negative
  exit != 0).
- **opencode plugin is not shipped.** The opencode auto-compression
  TypeScript plugin exists only as documentation; no plugin file is in this
  checkout. README, INSTALL.md, architecture.md, capability-matrix.md, and
  adapter-contract.md now state that, and `costmaxx install` scope (one MCP
  config file, backup, refuse-overwrite) is documented.

- **Immutable call ledger.** Schema migration v5 adds `call_ledger`, one
  immutable row per accepted command/tool call (harness, redacted command/cwd,
  category, reducer, raw and model-visible bytes/token estimates, policy
  recommendation, final guarded decision, distinct `reduction_attempted` vs
  `reduction_applied`, artifact/reduction IDs, exit code, rehydration flag,
  hook/error status, outcome enum). Rows are written atomically with the
  artifact/reduction metadata and guarded by an idempotency key, so a retry or
  duplicate subprocess cannot double count. `session_metrics` is retained only
  as a compatibility read model. Migration v6 normalizes v5 timestamps to a
  fixed-width UTC layout so `--since` windows and `ORDER BY event_timestamp`
  slice by real event time: plain RFC3339Nano trims trailing zeros, which
  inverts sub-second string order (`…:00.5Z` sorts after `…:00.55Z`) and used
  to drop in-window calls. Coverage:
  `tests/unit/ledger_test.go` (idempotency, atomic RecordCall, rehydration,
  deterministic report fixture with exact time-window boundaries, sub-second
  boundary slicing, concurrent inserts), `tests/integration/migration_test.go`
  (v4→v6 incremental, timestamp normalization, idempotent re-migration).
- **Correct metric semantics.** `costmaxx savings` and `costmaxx report` now
  aggregate ledger rows by actual event timestamp and separate calls observed,
  artifacts stored, reductions attempted, reductions applied, passthroughs,
  guard downgrades, preserve-full decisions, rehydrations, and errors. A
  processed artifact is never labelled "reduced" unless the compact text was
  the final model-visible response. `--since=0` reports all history.
- **Real active-path verifier restored.** `scripts/verify-active-path.py`
  exists and is executed by `scripts/verify-active-path.sh`. It drives the
  real built binary over MCP stdio and verifies command execution and exit
  propagation, artifact metadata + digest integrity, byte-for-byte retrieval,
  reduction record persistence, policy/guard behavior, ledger row creation,
  and no false saving on tiny or guard-downgraded output. It fails closed on
  missing files, malformed JSON, missing rows, wrong digests, wrong decisions,
  or bypasses. Positive and negative directions both pass (negative corrupts
  a stored digest and proves a non-zero failure). Coverage:
  `tests/integration/verify_active_path_test.go`.
- **Proof reproducibility.** `verify-live-results.py` now enforces the
  recorded binary hash via `--expect-binary-sha`. The retained 2026-08-05 raw
  evidence directory is absent from this checkout, so those numbers are
  documented, not locally verified; see docs/RESULTS.md for the exact blocker
  and the audit command.
- **Fresh live transcript proof.** A new 2026-09-02 run is retained locally at
  `results/20260902T-live-proof/` (ignored, compact bundle) and independently
  audits 20 fixtures × 3 repetitions: 60/60 active answer passes, 60/60 exact
  MCP calls, zero direct commands, zero rehydrations, and 55.4% lower
  model-visible token estimates. The one baseline miss is a control-model
  warning; `--require-baseline` still fails on it. The bundle is not committed,
  so a clean clone must reproduce or copy it before treating it as portable
  evidence.
- **Baseline control misses are warnings, not product failures.** The eval
  runner (`run-codex-eval.py`) exits `0` when the active arm and harness
  invariants pass. A baseline answer mismatch on a valid baseline transcript
  is classified as an explicit control miss (`baseline.control_miss` in
  `report.json`, a `Control miss` column/aggregate in `report.md`, and a
  console `WARN`) and does not fail the run — the active arm is the product
  claim, and the baseline is its no-CostMax control. Fail-closed behavior is
  unchanged: missing baseline transcripts, baseline subprocess/command errors,
  active errors, active answer mismatches, MCP bypasses, and rehydration
  violations all still fail the run, and `verify-live-results.py
  --require-baseline` still fails on the control miss. Answer checking is not
  weakened; the miss is reported everywhere it can be seen. Deterministic
  self-tests cover the classification, aggregation, and exit semantics
  (`python3 scripts/run-codex-eval.py --self-test`).
- **Hooks remain observe-only.** The hook path now writes ledger rows with
  harness `codex_hook`, outcome `reduction_attempted` at most (the model
  always sees unmodified output), and records malformed-payload fail-open
  events. No hook replaces tool output.
- **Privacy/classifier gaps closed.** The redactor now detects and removes
  AWS `aws_access_key_id` / `aws_secret_access_key` forms,
  `Authorization: Bearer ...`, and spaced/quoted secret assignments
  (including values with internal spaces). Command and working-directory
  strings are redacted before persistence (artifact metadata and ledger) and
  before being echoed in the envelope. The classifier now matches command
  tokens instead of substrings (no more `/tmp/test-data` → test false
  positives), recognizes bare `jest`/`mocha`/`rspec`/`vitest` and `find`
  regardless of `-name`, and trims leading whitespace before the JSON
  signature check. The dead `COSTMAX_DISABLE=1` claim was removed from the
  binary's `disable` command. Coverage: `tests/unit/privacy_test.go`,
  `tests/unit/config_redactor_test.go`, `tests/unit/classifier_edges_test.go`,
  `tests/unit/ledger_test.go` (command redaction),
  `tests/integration/hooks_observe_test.go` (malformed-payload fail-open).

## 2. Findings

### Bugs found and fixed during this audit

1. **ReadRange panics on inverted range** (internal/artifacts/store.go).
   `ReadRange(3, 1)` panicked: slice bounds out of range. Fixed with a clamp.
   No production caller today, but it is exported API used by evidence tooling.
   Regression test: TestReadRangeEdges.

2. **Signal-killed commands report Exit: -1** (internal/mcp/server.go).
   `kill -TERM $$` produced Exit: -1, losing the cause. Fixed to report
   128+signal (143 for SIGTERM). Test: TestStdioRunSignalDeath.

3. **Concurrent processes fail to start on one data dir** (internal/store/sqlite.go).
   Two costmaxx processes on the same HOME hit `SQLITE_BUSY` during migrate.
   Real risk: Codex hook invocations and the MCP server share ~/.costmax.
   Fixed with a bounded retry in Open() plus closing the DB handle on failure
   (the old code leaked the handle). Test: TestStdioConcurrentProcessesSameDataDir.

### Security findings (documented, not fixed)

4. **Redactor misses common secret formats.** Not detected:
   `aws_secret_access_key=...`, `Authorization: Bearer ...`, spaced
   assignments (`api_key = "..."`). Regexes require the keyword directly
   before `=` or `:` and do not include AWS or Bearer forms. Detected: SSN,
   JWT, email, `api_key=`/`token=`/`password:` without spaces, URLs with
   embedded credentials. Test: TestRedactorMissesCommonFormats.

5. **Command strings are not redacted.** The command line is echoed in the
   model-visible response and persisted unredacted in artifact metadata
   (SQLite). The model already knows the command it sent, so exposure is low,
   but a command containing a secret (e.g. curl with an inline token) lands
   in ~/.costmax/costmax.db in the clear. Output content is redacted before
   storage. Test: TestStdioSecretRedactedInResponseAndArtifact documents the
   split.

### Classifier quality findings (documented, not fixed)

6. **Substring false positives.** Any command containing "test" or "build"
   classifies as test/build: `cd /tmp/test-data && ls` -> test,
   `cat ~/build-notes.md` -> build. Commands are keyword-matched, not
   tokenized. Tests: TestPathWithTestSubstringIsFalsePositive,
   TestPathWithBuildSubstringIsFalsePositive.

7. **False negatives.** Bare `jest`, `mocha`, `rspec` (matchers require a
   trailing space), and `find . -type f` without `-name` (&& precedence in
   the classifier) fall through to terminal. Tests:
   TestTestCommandSubstrings, TestFindWithoutNameIsNotSearch.

8. **JSON signature is fragile.** Leading whitespace before `{` defeats the
   JSON classifier (falls to terminal). Test:
   TestJSONSignatureNeedsLeadingBrace.

### Verified by-design behavior

- Policy: passthrough at <= 160 raw tokens or when compact + 80 >= raw;
  preserve_full for binary and reducer-less output; artifact_required for
  terminal/generic; post-render guard downgrades false savings.
- Reducer gates: terminal > 1000 bytes, generic > 2000 bytes. Small outputs
  get no reducer and pass through.
- All reducers are deterministic under adversarial input (empty, ANSI,
  unicode, malformed, threshold-sized); no panics, no errors.
- Reducers can produce compact output larger than tiny inputs; the guard
  backstops the claim.
- Token estimator is len/4: CJK undercounts (0.75 tokens per char), emoji
  overcounts (1 token per 4-byte emoji). Policy comparisons are
  self-consistent because both sides use the same estimator.
- GC drift is the only storage inconsistency found.

## 6. Historical verdict

For the 2026-08-05 version under test, CostMax's claims held under this audit.
The honesty posture was intact:
hooks are observe-only (verified at the real-binary level), the guard
prevents false savings claims, artifacts round-trip byte-identically, and
the fresh 20x3 live run passes the strict transcript audit with 60/60 active
quality and 60.6% model-visible token reduction, reproducing the retained
run's numbers on a fresh binary.

Three real bugs found and fixed during the audit (ReadRange panic, signal
exit code -1, concurrent-start SQLITE_BUSY). The main quality gaps are the
redactor (misses AWS/Bearer/spaced-assignment formats) and the classifier
(substring false positives, trailing-space false negatives). COSTMAX_DISABLE
help text is a dead claim. GC leaves DB rows behind. None of these block the
supported claim, but the redactor gaps matter most if CostMax is pointed at
repositories whose command output carries credentials.

That audit proved the project within its then-stated boundaries: Codex-only,
opt-in MCP, deterministic fixtures, observe-only hooks, token estimates not
billed dollars. Hermes and OpenCode setup support was added later through the
shared MCP server and is covered by the current install/doctor tests.
